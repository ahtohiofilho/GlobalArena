# R222 — Base activity and extraordinary tasks

Approved concept, 24 November 2026. Base: R221.3 PR #620, 01f170df960c10663bc5415e4357ddd5fc141a3d, four CI gates passed. Manual R221.4 is partially accepted, not formally closed; see companion acceptance ledger. This is a design increment, no executable changes.

## Canonical semantics

Production is ordinary worker behavior; finite tasks temporarily take priority. Each worker retains exactly one base policy independently of current activity: manual local occupation (including selected crop where applicable), or automatic local marginal economic choice. The user-facing schedule is finite tasks followed by a single indefinite terminal base activity; the kernel should store base policy separately. No indefinite entry may block subsequent finite tasks. Selecting a crop as base stages the change directly, without a second Grow command; no committed mutation until all-ready. Movement is a finite task, not an autonomous migration policy; construction and improvement are finite objectives including required approach. Existing time fractions are used, remaining time goes to next finite task or base. An active frozen crossing must finish under existing rules; no teleportation or retroactive duration changes. Construction interruption preserves project funding and work. Preserve worker physical presence, natal identity, demand by actual activity/location/time, and production per actual slice. Base preference must not be overwritten by transient work or travel. Existing land transport/port operations remain valid continuous roles; whether their automatic economic ranking includes indirect service value is an unresolved design gate, not a reason to remove them. Coal is illustrative, not a newly authorized catalog item.

## Kernel transition and acceptance

R223 audit and adapt the existing FoundationWorkerOrderQueue, WorldState canonical state, FoundationPersistentOrderEditJournal and collective private-plan publication, CanonicalWorldStateHasher, FoundationPersistentWorkerTurnScheduler and FoundationTemporalEconomicTurnProjector.ProjectPersistent. Current scheduler uses continuous Occupation head and actual occupation on empty queue; cannot simply change UI labels. Keep base policy in canonical versioned state with independent replay and exact deterministic ordering. Define migration of existing occupation/crop and pending queues explicitly: do not silently drop, reorder or reinterpret unreachable tail orders. Preserve old hash/save contracts when new mode disabled; explicit opt-in until verified. Newborn initialization and invalid manual occupation at a destination (including water/ice or no yield) require explicit policy before activation; never fabricate output or choose automatic replacement for manual mode silently. Initial R223 can isolate manual fallback before automatic economic policy is available; distinguish unavailable automatic resolution from valid zero output. No new commodity, resource stocks, buyer wallets, physical construction inputs, nutrition multiplier or demographic activation. Money and labor construction, opening capital/current-cycle freight, next-cycle activation, actual time slices, one collective close and independently derived replay stay intact.

Regression cases: base edit private until commit; manual crop retained across travel/build/interrupt; 0.6 construction + 0.4 base output and presence/demand, multiple finite tasks in one turn, completion on exact boundary, no eligible work, frozen crossing across turns, reorder/interrupt without lost project work, old mode hashes, newborn and ownership boundaries. Check sales/food attribution and transient land/port service based on actual slices, not base label. Reject invalid or duplicate base entries. Test at actual physical nodes with canonical geography.
