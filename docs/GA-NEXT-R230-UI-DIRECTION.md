# R230 — UI direction (approved 2026-11-25)

R229.5.2 visual acceptance: movable/resize city window worked; no change to economic mechanics. R230.1 numeric presentation: physical quantities at most three decimals, money with $ and two decimals, counts integer, percentages usually one decimal. English canonical UI, invariant decimal separator, exact ledger unaffected. Display tiny positive amounts as <0.001 or <$0.01 to distinguish from zero. Editable monetary commands retain exact six-micro-decimal capacity; never feed rounded display back to an order. QA/debug logs retain raw precision. Initial formatting pass covers current city production/connections, construction, treasury, civilization, local logistics, travel and legacy port readouts; audit remaining surfaces as they are migrated. 

Right column: fixed compact width, four independent contextual layers Unit, Infrastructure, Terrain, Planet; Planet fixed at bottom, others can scroll. Architecture and canonical data binding before visual polish. No fake stats/assets or unsupported actions. Infrastructure must respect actual edge-based assets, not invent tile buildings. Unit and infrastructure commands contextual; terrain primarily informative. Column is NOT exclusive command surface: tactical map must support direct orders, retaining proven gestures and worker selection; use one authoritative command path regardless of entry surface. Miniplanet command interaction is exploratory, not committed behavior; preserve navigation and avoid accidental orders. Later increments R230.2 shell, R230.3 Unit, R230.4 Infrastructure, R230.5 Terrain, R230.6 Planet, R230.7 polish. No kernel changes. CI and visual acceptance required.
